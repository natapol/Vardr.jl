**Vardr.jl** is a general-purpose framework for building **digital twins** in Julia.
(In Norse folklore a *vörðr* is a warden spirit that follows a person as their double.)

A digital twin is a mechanistic model that stays synchronized with a real system through
incoming data, and can answer "what happens next?" and "what if?" questions. Vardr builds on
[SciML](https://sciml.ai): any `ODEProblem`, including those generated by
[ModelingToolkit](https://github.com/SciML/ModelingToolkit.jl), can be the core of a twin.
Vardr adds the twin layer:

| | |
|---|---|
| **Belief** | an ensemble or particle representation of the system's state, with optional joint estimation of model parameters |
| **Data assimilation** | ensemble Kalman filter (`EnKF`) and bootstrap particle filter (`ParticleFilter`); missing sensor values are handled |
| **What-if** | probabilistic `forecast`s, and `scenario`s with interventions (`SetParameter`, `SetState`, `Event`), compared with `compare` |
| **Calibration** | offline maximum-likelihood parameter fitting with any Optimization.jl optimizer |
| **Live operation** | `run!` a twin on a data stream (`TableSource`, `ChannelSource`, or your own), with sinks, wall-clock ticks and late-data handling |
| **Persistence** | `snapshot` / `restore!` of the twin's state to JLD2 |

## Quick start

```julia
using Vardr, Distributions, LinearAlgebra

# 1. Model: a damped oscillator x'' = -k x - c x'
osc(u, p, t) = [u[2], -p[1] * u[1] - p[2] * u[2]]
model = TwinModel(osc, [1.0, 0.0], [4.0, 0.1]; states = [:x, :v], params = [:k, :c])

# 2. Sensors: x is measured with noise σ = 0.05
sensors = ObservationModel(model, [:x], 0.05)

# 3. Twin: an EnKF over [x, v, k], so the spring constant k is learned online
twin = Twin(model, sensors; estimator = EnKF(N = 100), estimate = [:k],
    prior = MvNormal([1.0, 0.0, 4.0], Diagonal([0.5, 0.5, 1.0] .^ 2)),
    process_noise = [0.01, 0.01, 0.01])

# 4. Synchronize with data as it arrives
for (t, x) in measurements
    step!(twin, Observation(t, x))
end
twin[:x], uncertainty(twin, :x), twin[:k]

# 5. Ask questions
baseline = forecast(twin, 20.0)
damped   = scenario(twin, [SetParameter(12.0, :c => 1.0)], 20.0; name = "extra damping")
compare(baseline, damped; var = :x)
```

### ModelingToolkit models

```julia
using ModelingToolkit
using ModelingToolkit: t_nounits as t, D_nounits as D
@parameters β γ
@variables S(t) I(t) R(t)
@mtkcompile sir = System([D(S) ~ -β*S*I, D(I) ~ β*S*I - γ*I, D(R) ~ γ*I], t)
prob = ODEProblem(sir, [S => 0.99, I => 0.01, R => 0.0, β => 0.5, γ => 0.1], (0.0, 1.0))

twin = Twin(TwinModel(prob), ObservationModel(TwinModel(prob), [I], 0.002); estimate = [β])
twin[I], twin[β]
```

### Live data

```julia
src = ChannelSource()
runner = run!(twin, src; sinks = [SnapshotSink("twin.jld2"; every = 100)], async = true)
put!(src, Observation(t, y))   # from your MQTT/HTTP/serial callback
state(twin)                    # query at any time; the twin is lock-protected
stop!(runner)
```

## Examples

[`examples/`](examples/README.md) contains complete, runnable twins with ground truth:

| Example | System | What it demonstrates |
|---|---|---|
| [`oscillator_twin.jl`](examples/oscillator_twin.jl) | Damped oscillator | The basics: joint state–parameter EnKF, forecast, a what-if `scenario`, `compare` |
| [`sir_epidemic_twin.jl`](examples/sir_epidemic_twin.jl) | SIR epidemic (ModelingToolkit) | Symbolic models, replaying data with `TableSource` + `run!`, intervention scenarios |
| [`lorenz63_twin.jl`](examples/lorenz63_twin.jl) | Lorenz-63 (chaotic) | Keeping a chaotic system synchronized from one observed variable; forecast skill vs ensemble spread |
| [`pkpd_patient_twin.jl`](examples/pkpd_patient_twin.jl) | Two-compartment PK/PD | Personalized dosing: dosing callbacks, sparse mixed measurements (`NaN`), comparing regimens for efficacy and toxicity |
| [`thermal_room_twin.jl`](examples/thermal_room_twin.jl) | 2R2C building with a thermostat | Live operation: `ChannelSource`, alert sinks, `SnapshotSink`, `WallClock` outages, retrofit what-ifs |
| [`heat_rod_twin.jl`](examples/heat_rod_twin.jl) | 1-D heat equation, 40 cells | A high-dimensional (PDE) twin with covariance localization |
| [`tank_leak_detection_twin.jl`](examples/tank_leak_detection_twin.jl) | Three-tank process (ModelingToolkit) | Fault detection with unmeasured states, and operator decision support |
