Vardr.Vardr — Module
Vardr

A general-purpose framework for building digital twins on top of SciML.

A digital twin couples a mechanistic model (any ODEProblem, including those generated by ModelingToolkit) with a probabilistic belief about the real system's state, keeps that belief synchronized with incoming observations (data assimilation), and answers forecast and what-if questions.

See TwinModel, ObservationModel, Twin.

Vardr.AbstractDataSource — Type
abstract type AbstractDataSource

A stream of Observations feeding a running twin (see run!).

To add a source, subtype AbstractDataSource and implement Vardr.start(src)::Channel{Observation}. If the source creates that channel itself, also define Vardr.owns_channel(src) = true so the runner can close it on stop!.

Vardr.EnKF — Type
struct EnKF{L} <: AbstractEstimator

Stochastic ensemble Kalman filter (perturbed observations).

EnKF(; N = 50, inflation = 1.0, localization = nothing)

Keywords

  • N: ensemble size.

  • inflation: multiplicative inflation of the ensemble anomalies before each update (values slightly above 1, such as 1.02, counteract ensemble collapse).

  • localization: Schur-product covariance localization for the model states, given as a tuple (Lxy, Lyy). Lxy (nu × ny) tapers the state–observation covariance and Lyy (ny × ny) the observation–observation covariance, where nu is the number of model states and ny the number of observed outputs. Both must come from the same correlation function, so that the state gain is the exact Kalman gain of the localized covariance. Tapering only Lxy can inflate the spread at the sensors and make the filter diverge. If the observation model observes states directly (ObservationModel(model, vars, σ)), passing Lxy alone is enough: Lyy is then the rows of Lxy at the observed states.

    Estimated parameters are global quantities, so they are always updated with the unlocalized gain.

  • N::Int64

  • inflation::Float64

  • localization::Any

Vardr.ObservationModel — Type
struct ObservationModel{H}

Maps a model state to what the sensors measure: y = h(u, p, t) + ε, with ε ~ N(0, R).

Constructors

ObservationModel(model, vars, σ)
ObservationModel(h, R; names)

The first form observes model states directly. vars is a vector of state names or indices, and σ is a scalar or a vector of measurement standard deviations. The second form takes an arbitrary function h(u, p, t) -> Vector and a measurement covariance matrix R (or a vector of standard deviations).

  • h::Any: Measurement function h(u, p, t).

  • R::Matrix{Float64}: Measurement noise covariance.

  • names::Vector{Symbol}: Names of the measured outputs.

Vardr.ParticleFilter — Type
struct ParticleFilter <: AbstractEstimator

Bootstrap (sequential importance resampling) particle filter. Suited to strongly nonlinear or non-Gaussian problems; needs more members than the EnKF.

ParticleFilter(; N = 500, resample_threshold = 0.5, jitter = 0.0)

Keywords

  • N: number of particles.
  • resample_threshold: resample when the effective sample size drops below this fraction of N.
  • jitter: after resampling, perturb particles by this fraction of the posterior standard deviation (regularization against sample impoverishment).

  • N::Int64

  • resample_threshold::Float64

  • jitter::Float64

Vardr.Twin — Type
mutable struct Twin{M<:TwinModel, O, E<:AbstractEstimator, B<:AbstractBelief, P, R<:Random.AbstractRNG}

A digital twin: a model, a belief about the real system's state, and the machinery to keep that belief synchronized with observations.

Twin(model, obs = nothing; estimator = EnKF(), estimate = [], prior = nothing,
     t0 = model.prob.tspan[1], process_noise = 0, bounds = nothing,
     rng = Random.default_rng(), name = "twin")

Keywords

  • estimate: parameters to estimate jointly with the states (augmented state z = [u; θ]).
  • prior: initial belief over z. Either a Distributions multivariate distribution, a matrix whose columns are members, or nothing for a Gaussian with 10% relative spread around the model's nominal u0 and parameters.
  • process_noise: model error, as standard deviation per unit time of each component of z (scalar or vector). Applied as a random walk during predict!. A small value on estimated parameters keeps their ensemble from collapsing.
  • bounds: (lower, upper) vectors over z. Members are clamped after every prediction and update, for example to keep concentrations non-negative.

  • name::String

  • model::TwinModel

  • obs::Any: Observation model, or nothing for a twin that is only simulated.

  • estimator::AbstractEstimator

  • belief::AbstractBelief

  • t::Float64: Current model time of the belief.

  • estimated::Vector{Any}: Parameters estimated online (appended to the state).

  • p::Any: Parameter object shared by all members (estimated entries are overridden per member).

  • process_noise::Vector{Float64}

  • lower::Vector{Float64}

  • upper::Vector{Float64}

  • history::Vardr.History

  • rng::Random.AbstractRNG

  • lock::ReentrantLock

Vardr.TwinModel — Type
struct TwinModel{P<:SciMLBase.ODEProblem, A, K}

The mechanistic core of a twin: an ODEProblem plus the solver used to advance it.

Any ODEProblem works, including one built from a ModelingToolkit system (ODEProblem(sys, u0map, tspan, pmap)), in which case states and parameters can be referred to by their symbolic names.

Constructors

TwinModel(prob::ODEProblem; alg = Tsit5(), solve_kwargs...)
TwinModel(f, u0, p; states = nothing, params = nothing, t0 = 0.0, alg = Tsit5(), solve_kwargs...)

The second form wraps an out-of-place right-hand side f(u, p, t) (or in-place f(du, u, p, t)). Pass states/params as vectors of Symbols to enable name-based indexing without ModelingToolkit.

  • prob::SciMLBase.ODEProblem: Template problem; its u0, p and tspan[1] are the nominal initial conditions.

  • alg::Any: ODE solver algorithm.

  • solve_kwargs::Any: Extra keyword arguments forwarded to solve.

Vardr.WallClock — Type
struct WallClock

Keeps a running twin advancing through data outages. Whenever interval wall-clock seconds pass with no observation, the twin predicts dt model time units ahead. Set dt to roughly the model time that elapses in interval seconds of the real system.

Ticks are provisional. Before the first tick of a quiet period the runner checkpoints the belief. If an observation then arrives that the ticks have already moved past, the twin rolls back to the checkpoint and assimilates it, so data is never dropped because of a tick. The rolled-back tick records are removed from the history.

  • interval::Float64

  • dt::Float64

Vardr.calibrate! — Method
calibrate!(twin, data, params; alg, lb = nothing, ub = nothing, adtype = SciMLBase.NoAD(), u0 = state(twin), solve_kwargs...)

Fit model parameters params (names or indices) to a batch of observations by maximizing the Gaussian likelihood under the twin's observation model, simulating from u0 at twin.t. All observations must be at or after twin.t.

alg is any Optimization.jl optimizer, e.g. NelderMead() after using OptimizationOptimJL. Gradient-based optimizers need an adtype such as AutoForwardDiff().

On success the fitted values replace the twin's fixed parameters. If a parameter is also estimated online, its member values are shifted so that their mean equals the fitted value. Returns the Optimization.jl solution.

Vardr.forecast — Method
forecast(twin, tend; saveat = range(twin.t, tend; length = 101), nsamples, interventions = [], name = "forecast", rng)

Propagate samples from the twin's current belief to tend without changing the twin. Returns a TwinForecast. nsamples defaults to the number of members. Each sample's estimated parameters are those of the member it was drawn from, so parameter uncertainty is carried into the forecast. Process noise is not added.

Vardr.run! — Method
run!(twin, source; sinks = [], until = Inf, clock = nothing, on_error = :stop, async = false)

Keep twin synchronized with a live AbstractDataSource: every incoming observation is assimilated with step!, then passed to each sink.

  • Observations older than the twin's current time (late or out of order) are dropped and counted in runner.late, unless only provisional clock ticks have moved the twin past them (see WallClock).
  • until: stop once model time reaches this value.
  • clock: a WallClock that advances the twin when no data arrives for a while.
  • on_error: :stop ends the run and rethrows on wait; :skip logs a warning, counts the failure and continues.
  • async = true returns the TwinRunner immediately. Otherwise run! blocks until the source is exhausted, until is reached, or stop! is called.

While a run is in progress, other tasks can still query the twin (state(twin), forecast(twin, …)), because every operation on the twin takes its lock.

Vardr.History — Type
mutable struct History

Record of the twin's belief after every prediction and assimilation.

History is a Tables.jl column table with columns t, kind (:init, :predict or :update), then <name> (posterior mean) and <name>_std for every augmented state component. Turn it into a DataFrame with DataFrame(history(twin)).

  • names::Vector{Symbol}: Names of the augmented state components.

  • t::Vector{Float64}

  • kind::Vector{Symbol}

  • mean::Vector{Vector{Float64}}

  • std::Vector{Vector{Float64}}

  • observations::Vector{Observation}: Observations that have been assimilated.
