Vardr.Vardr — Module
Vardr

A general-purpose framework for building digital twins on top of SciML.

A digital twin couples a model of the real system with a probabilistic belief about the system's state, keeps that belief synchronized with incoming observations (data assimilation), and answers forecast and what-if questions. The model can be an ODE (any ODEProblem, including those generated by ModelingToolkit), a neural or hybrid ODE, or an agent-based simulation.

See AbstractTwinModel, ObservationModel, Twin.

Vardr.AbstractBelief — Type
abstract type AbstractBelief

A probabilistic description of the twin's (augmented) state z = [u; θ], where u are the model states and θ are the parameters being estimated online.

Members of an AgentModel also carry a latent simulation object each, in belief.latent (empty for other models).

Vardr.AbstractTwinModel — Type
abstract type AbstractTwinModel

Supertype of the process models a Twin can run:

  • ODEModel: an ordinary differential equation (any SciML ODEProblem, including ModelingToolkit models);
  • NeuralODEModel: an ODE whose right-hand side is, or contains, a neural network (a neural ODE or universal differential equation);
  • AgentModel: a stochastic agent-based simulation, tracked through summary quantities.

Every model exposes a state vector u with named components and a parameter object p. Filters, forecasts and calibration only see u and p. A model can also give each member a latent object that holds everything else, such as the individual agents of an agent-based model.

Implementing a new model type

A subtype M <: AbstractTwinModel defines:

MethodReturns
nstates(m), statenames(m)size and names of u
user_parameters(m)parameter names (empty if parameters are referred to by index)
nominal_state(m), nominal_params(m), initial_time(m)nominal u0, p and t0
getparam(m, p, s), setparam!(m, p, s, v)read and write one parameter of p
advance(m, u, latent, p, t0, t1, rng; callback)(u, latent) at t1
trajectory(m, u, latent, p, t0, ts, rng; interventions, strict)the states at times ts

Models with a latent object also define haslatent(m) = true, init_latent(m, u, p, rng) returning a consistent (u, latent) pair and, to be usable with the EnKF, canlift(m) = true and lift(m, latent, u, p, rng), which adjusts latent to match an updated u.

Vardr.AgentModel — Type
struct AgentModel{I, S, F, L} <: AbstractTwinModel

A stochastic agent-based (individual-based) model, stepped in fixed time steps.

AgentModel(init, step!, summarize, u0, p; states = nothing, params = nothing,
    dt = 1.0, t0 = 0.0, lift = nothing)

Each member of the twin's belief owns a complete simulation, sim: the agents and anything else the model needs. The twin tracks the simulation through a short summary state u = summarize(sim), such as the number of agents in each compartment. Observation models, forecasts, the history and the filters work on u; the simulation is the member's latent state.

Arguments

  • init(u, p, rng) -> sim: build one member's simulation for parameters p. u is a summary state drawn from the twin's prior; use it to set the initial condition (for example round it to agent counts), or ignore it.
  • step!(sim, p, t, rng): advance sim in place by one step of length dt, starting at time t. Draw all randomness from rng.
  • summarize(sim) -> Vector: the summary state; its length must match u0.
  • u0, p: nominal summary state and parameter vector.

Keywords

  • states, params: names of the summary components and parameters.
  • dt: time step. Observation and forecast times must lie on the step grid.
  • lift(sim, u, p, rng) -> sim: optional. Change a simulation so that its summary becomes (approximately) u, for example by moving agents between compartments. Only the EnKF needs it, because it shifts members' states directly. The ParticleFilter only reweights and copies whole simulations, so it works with any agent model.

Each member gets its own random number generator for every prediction, so results are reproducible from the twin's rng and independent of the number of threads. Members that the particle filter duplicates are deep copies that then evolve independently.

  • init::Any

  • step!::Any

  • summarize::Any

  • lift::Any: Optional lift(sim, u, p, rng), or nothing.

  • u0::Vector{Float64}

  • p::Vector{Float64}

  • states::Vector{Symbol}

  • params::Vector{Symbol}

  • dt::Float64

  • t0::Float64

Vardr.EnKF — Type
struct EnKF{L} <: AbstractEstimator

Stochastic ensemble Kalman filter (perturbed observations).

EnKF(; N = 50, inflation = 1.0, localization = nothing)

Keywords

  • N: ensemble size.

  • inflation: multiplicative inflation of the ensemble anomalies before each update (values slightly above 1, such as 1.02, counteract ensemble collapse).

  • localization: Schur-product covariance localization for the model states, given as a tuple (Lxy, Lyy). Lxy (nu × ny) tapers the state–observation covariance and Lyy (ny × ny) the observation–observation covariance, where nu is the number of model states and ny the number of observed outputs. Both must come from the same correlation function, so that the state gain is the exact Kalman gain of the localized covariance. Tapering only Lxy can inflate the spread at the sensors and make the filter diverge. If the observation model observes states directly (ObservationModel(model, vars, σ)), passing Lxy alone is enough: Lyy is then the rows of Lxy at the observed states.

    Estimated parameters are global quantities, so they are always updated with the unlocalized gain.

For an AgentModel, the updated summary states are passed to the model's lift function, which adjusts each member's simulation to match.

  • N::Int64

  • inflation::Float64

  • localization::Any

Vardr.MLP — Type
struct MLP{F}

A small fully connected neural network (multilayer perceptron) whose weights are a flat vector, so they can be estimated like any other parameter.

MLP(sizes...; activation = tanh)
net(x, w)          # evaluate with weight vector w

MLP(2, 16, 16, 1) maps 2 inputs through two hidden layers of 16 units to 1 output. activation is applied after every layer except the last (which is linear). nweights gives the length of w, and init_weights a random starting point. The network is plain Julia, so it works with dual numbers (gradient-based calibration) and needs no deep-learning package.

  • sizes::Vector{Int64}: Layer widths, from inputs to outputs.

  • activation::Any

Vardr.NeuralODEModel — Type
struct NeuralODEModel{N, M<:ODEModel} <: AbstractTwinModel

An ODE whose right-hand side is, or contains, a neural network.

NeuralODEModel(network, u0; f = nothing, p = Float64[], weights = nothing,
    states = nothing, params = nothing, rng = Random.default_rng(), t0 = 0.0,
    alg = Tsit5(), solve_kwargs...)
  • Neural ODE (f = nothing): du/dt = network(u, w). The network learns all of the dynamics.
  • Universal differential equation (hybrid model): du/dt = f(u, p, t, nn), where nn(x) = network(x, w). Write the known physics in f and call nn for the part that is unknown, for example a reaction rate.

network(x, w) is any callable that takes an input vector and a flat weight vector: an MLP, or a model from a deep-learning package wrapped in a closure. weights are the starting weights; by default they come from init_weights(rng, network), which MLP supports.

The weights are parameters named nn1, nn2, … (see weightnames), after the mechanistic parameters p. Train them with calibrate! (offline, preferably gradient-based), or estimate them online like any other parameter (estimate = weightnames(model)).

  • network::Any

  • ode::ODEModel: The equivalent ODE model, whose parameters are [p; w].

  • nparams::Int64: Number of mechanistic parameters (before the weights).

Vardr.ODEModel — Type
struct ODEModel{P<:SciMLBase.ODEProblem, A, K} <: AbstractTwinModel

A process model given by an ordinary differential equation: an ODEProblem plus the solver used to advance it.

Any ODEProblem works, including one built from a ModelingToolkit system (ODEProblem(sys, u0map, tspan, pmap)), in which case states and parameters can be referred to by their symbolic names.

Constructors

ODEModel(prob::ODEProblem; alg = Tsit5(), solve_kwargs...)
ODEModel(f, u0, p; states = nothing, params = nothing, t0 = 0.0, alg = Tsit5(), solve_kwargs...)

The second form wraps an out-of-place right-hand side f(u, p, t) (or in-place f(du, u, p, t)). Pass states/params as vectors of Symbols to enable name-based indexing without ModelingToolkit.

  • prob::SciMLBase.ODEProblem: Template problem; its u0, p and tspan[1] are the nominal initial conditions.

  • alg::Any: ODE solver algorithm.

  • solve_kwargs::Any: Extra keyword arguments forwarded to solve.

struct ParticleFilter <: AbstractEstimator

Bootstrap (sequential importance resampling) particle filter. Suited to strongly nonlinear or non-Gaussian problems; needs more members than the EnKF.

Vardr.Twin — Type
mutable struct Twin{M<:AbstractTwinModel, O, E<:AbstractEstimator, B<:AbstractBelief, P, R<:Random.AbstractRNG}

A digital twin: a model, a belief about the real system's state, and the machinery to keep that belief synchronized with observations.

Twin(model, obs = nothing; estimator = EnKF(), estimate = [], prior = nothing,
     t0 = initial time of the model, process_noise = 0, bounds = nothing,
     rng = Random.default_rng(), name = "twin")

Keywords

  • estimate: parameters to estimate jointly with the states (augmented state z = [u; θ]).
  • prior: initial belief over z. Either a Distributions multivariate distribution, a matrix whose columns are members, or nothing for a Gaussian with 10% relative spread around the model's nominal u0 and parameters.
  • process_noise: model error, as standard deviation per unit time of each component of z (scalar or vector). Applied as a random walk during predict!. A small value on estimated parameters keeps their ensemble from collapsing.
  • bounds: (lower, upper) vectors over z. Members are clamped after every prediction and update, for example to keep concentrations non-negative.

model is any AbstractTwinModel. For an AgentModel, each member also gets its own simulation, built by the model's init from the member's prior draw. Its state rows then come from the simulation, so process_noise and bounds may only be set for the estimated parameters.

  • name::String

  • model::AbstractTwinModel

  • obs::Any: Observation model, or nothing for a twin that is only simulated.

  • estimator::AbstractEstimator

  • belief::AbstractBelief

  • t::Float64: Current model time of the belief.

  • estimated::Vector{Any}: Parameters estimated online (appended to the state).

  • p::Any: Parameter object shared by all members (estimated entries are overridden per member).

  • process_noise::Vector{Float64}

  • lower::Vector{Float64}

  • upper::Vector{Float64}

  • history::Vardr.History

  • rng::Random.AbstractRNG

  • lock::ReentrantLock

Vardr.WallClock — Type
struct WallClock

Keeps a running twin advancing through data outages. Whenever interval wall-clock seconds pass with no observation, the twin predicts dt model time units ahead. Set dt to roughly the model time that elapses in interval seconds of the real system.

Ticks are provisional. Before the first tick of a quiet period the runner checkpoints the belief. If an observation then arrives that the ticks have already moved past, the twin rolls back to the checkpoint and assimilates it, so data is never dropped because of a tick. The rolled-back tick records are removed from the history.

  • interval::Float64

  • dt::Float64

Vardr.calibrate! — Method
calibrate!(twin, data, params; alg, lb = nothing, ub = nothing, adtype = SciMLBase.NoAD(), u0 = state(twin), nsims = 1, seed = 1, solve_kwargs...)

Fit model parameters params (names or indices) to a batch of observations by maximizing the Gaussian likelihood under the twin's observation model, simulating from u0 at twin.t. All observations must be at or after twin.t.

alg is any Optimization.jl optimizer, e.g. NelderMead() after using OptimizationOptimJL. Gradient-based optimizers need an adtype such as AutoForwardDiff() (after using ForwardDiff). This is the way to train the weights of a NeuralODEModel: pass weightnames(model) as params.

For a stochastic AgentModel, each evaluation of the loss simulates nsims replicates from u0 with fixed seeds (common random numbers, so the loss is a deterministic function of the parameters), and fits the mean of their summary states. This simulated-moments fit ignores the model's own randomness; it gives a starting point, which online estimation with a ParticleFilter can refine.

On success the fitted values replace the twin's fixed parameters. If a parameter is also estimated online, its member values are shifted so that their mean equals the fitted value. Returns the Optimization.jl solution.

Vardr.predict! — Method
predict!(twin, t)

Advance every member of the twin's belief from twin.t to model time t, adding process noise. Members are integrated in parallel across Julia threads.

If an integration fails, an IntegrationError is thrown and the belief of an ODE twin is left unchanged. (Agent simulations are advanced in place, so after a failed step their state is undefined.)

Vardr.run! — Method
run!(twin, source; sinks = [], until = Inf, clock = nothing, on_error = :stop, async = false)

Keep twin synchronized with a live AbstractDataSource: every incoming observation is assimilated with step!, then passed to each sink.

  • Observations older than the twin's current time (late or out of order) are dropped and counted in runner.late, unless only provisional clock ticks have moved the twin past them (see WallClock).
  • until: stop once model time reaches this value.
  • clock: a WallClock that advances the twin when no data arrives for a while.
  • on_error: :stop ends the run and rethrows on wait; :skip logs a warning, counts the failure and continues.
  • async = true returns the TwinRunner immediately. Otherwise run! blocks until the source is exhausted, until is reached, or stop! is called.

While a run is in progress, other tasks can still query the twin (state(twin), forecast(twin, …)), because every operation on the twin takes its lock.

Vardr.History — Type
mutable struct History

Record of the twin's belief after every prediction and assimilation.

History is a Tables.jl column table with columns t, kind (:init, :predict or :update), then <name> (posterior mean) and <name>_std for every augmented state component. Turn it into a DataFrame with DataFrame(history(twin)).

  • names::Vector{Symbol}: Names of the augmented state components.

  • t::Vector{Float64}

  • kind::Vector{Symbol}

  • mean::Vector{Vector{Float64}}

  • std::Vector{Vector{Float64}}

  • observations::Vector{Observation}: Observations that have been assimilated.
