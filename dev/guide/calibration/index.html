Calibration and persistence

Offline calibration vs online estimation

Vardr offers two ways to learn parameters:

calibrate! (offline)estimate = [...] (online)
Dataa batch of historical observationsone observation at a time
Methodmaximum likelihood, by optimizationBayesian filtering
Resultpoint estimates, written into the twin's fixed parametersa posterior that evolves
Use forcommissioning: fitting a new twin to historical datafollowing a system as it runs and drifts

They work well together: calibrate most parameters once on history, then estimate the few that drift online. The objective that calibrate! minimizes, and when parameters can be identified at all, are covered in Calibration: maximum likelihood and Identifiability.

calibrate!

calibrate!(twin, data, params; alg, lb = nothing, ub = nothing,
           adtype = SciMLBase.NoAD(), u0 = state(twin), solve_kwargs...)

It simulates the model from u0 at twin.t through all data, and minimizes the Gaussian negative log-likelihood under the twin's observation model. Missing (NaN) values are ignored.

using OptimizationOptimJL: NelderMead

twin = Twin(model, sensors; estimator = EnKF(N = 50), rng = Xoshiro(1))
sol = calibrate!(twin, measurements, [:k, :c]; alg = NelderMead(), u0 = [1.5, 0.0])
sol.u, paramvalues(twin)
([3.0015025967187885, 0.099258201817321], [:k => 3.0015025967187885, :c => 0.099258201817321])
  • params: parameter names (or indices) to fit; the others stay fixed.
  • alg: any Optimization.jl optimizer. NelderMead() needs no gradients. For gradient-based optimizers (LBFGS()), pass adtype = AutoForwardDiff(), and make sure your model function accepts dual numbers (avoid Float64[...] literals inside f).
  • lb, ub: bounds, for optimizers that support them.
  • u0: the initial state of the simulation. It defaults to the twin's current mean state. If the initial state is uncertain too, include it in your own loss, or start the data a little later and let the filter handle it.
  • Extra keywords (maxiters = 500) go to Optimization.solve.

After calibration, the fitted values become the twin's fixed parameters. If a calibrated parameter is also in estimate, its members are shifted so that their mean equals the fitted value, keeping their spread.

All observations must be at or after twin.t. Calibrate a fresh twin on history, then assimilate newer data.

Snapshots

A twin that runs for weeks must survive restarts. snapshot saves its dynamic state to a JLD2 file: time, belief, fixed parameters, history and RNG state.

twin = Twin(model, sensors; estimator = EnKF(N = 50), estimate = [:k],
    process_noise = 0.01, rng = Xoshiro(1))
foreach(o -> step!(twin, o), measurements[1:50])
path = snapshot(joinpath(mktempdir(), "twin.jld2"), twin)
"/tmp/jl_5EpNmy/twin.jld2"

Code is not saved: the model function, observation function and estimator settings belong in your source code. To restore, build the twin with the same code, then load the state:

build() = Twin(model, sensors; estimator = EnKF(N = 50), estimate = [:k],
    process_noise = 0.01, rng = Xoshiro(0))
restored = restore!(build(), path)
foreach(o -> step!(restored, o), measurements[51:end])
foreach(o -> step!(twin, o), measurements[51:end])
restored[:k] == twin[:k]          # continues exactly where it left off
true

restore! checks that the snapshot fits the twin: the same state dimension and the same belief type. With an explicit RNG of the same type (Xoshiro), the restored twin continues bit-for-bit identically.

While running live, SnapshotSink writes snapshots periodically and at shutdown. See Running live.
