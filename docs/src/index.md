# Vardr.jl

Vardr is a general-purpose framework for building **digital twins** on top of
[SciML](https://sciml.ai). The model at the core of a twin can be mechanistic,
learned, or both, and continuous or agent-based.

A twin in Vardr has four parts:

1. A **process model** (an [`AbstractTwinModel`](@ref)):
   - an [`ODEModel`](@ref): any `ODEProblem`, for example one generated by
     ModelingToolkit, plus the solver used to advance it;
   - a [`NeuralODEModel`](@ref): a neural ODE, or a hybrid model in which a neural
     network learns the unknown part of known equations;
   - an [`AgentModel`](@ref): a stochastic agent-based simulation, tracked through
     summary quantities.
2. An [`ObservationModel`](@ref): what the sensors measure, `y = h(u, p, t) + ε`.
3. A **belief** about the real system's augmented state `z = [u; θ]`: the model states
   `u` and any parameters `θ` estimated online. It is represented by an ensemble
   ([`EnsembleBelief`](@ref)) or weighted particles ([`ParticleBelief`](@ref)).
4. An **estimator** that keeps the belief synchronized with data: [`EnKF`](@ref),
   [`ParticleFilter`](@ref), or [`NoAssimilation`](@ref) (open loop).

```
data ──▶ step!(twin, obs) = predict!(twin, obs.t) + assimilate!(twin, obs)
                                 │                          │
                    integrate every member        update belief with obs
                                 └──────── twin.belief ─────┘
                                               │
                    forecast · scenario · compare · calibrate! · snapshot
```

## Where to start

- New to Vardr? Follow the [Tutorial](@ref "Tutorial: your first twin"): one twin, built
  step by step, in about 10 minutes.
- Building your own twin? Follow the [Step-by-step workflow](@ref), which goes from
  the question to deployment with a check at every step.
- Working in pharma or bioprocessing? The [Case study: a bioprocess twin](@ref)
  applies the workflow to a fed-batch bioreactor and a risk-constrained feed decision.
- Can you trust the results? [Case study: validating Vardr against exact answers](@ref)
  checks every estimator against exact solutions, with acceptance criteria.
- Want to understand the methods? The **Theory** chapters derive what Vardr computes,
  with references: [Digital twins and state-space models](@ref),
  [Bayesian filtering and data assimilation](@ref), and
  [Prediction, calibration and verification](@ref).
- Using a twin for decisions: [Forecasts and what-if scenarios](@ref).
- Deploying: [Running live](@ref) and [Calibration and persistence](@ref).
- Something wrong: [Troubleshooting](@ref).

## Installation

Vardr is not yet registered. Install it from GitHub:

```julia
using Pkg
Pkg.add(url = "https://github.com/natapol/Vardr.jl")
```

You will usually also want `Distributions` (for priors), and `ModelingToolkit` if you
write models symbolically.

| Stage | Functions |
|:---|:---|
| Build | [`ODEModel`](@ref), [`NeuralODEModel`](@ref), [`AgentModel`](@ref), [`ObservationModel`](@ref), [`Twin`](@ref) |
| Synchronize | [`predict!`](@ref), [`assimilate!`](@ref), [`step!`](@ref) |
| Query | [`state`](@ref), [`uncertainty`](@ref), [`paramvalues`](@ref), `twin[:x]`, [`history`](@ref) |

| Operate live | [`run!`](@ref) with an [`AbstractDataSource`](@ref) and [`AbstractSink`](@ref)s; [`stop!`](@ref) |
| Persist | [`snapshot`](@ref), [`restore!`](@ref) |

## Tips

- Start Julia with threads (`julia -t auto`). Ensemble members are integrated in parallel.
- Give estimated parameters a small `process_noise`, so their ensemble spread does not
  collapse and the twin can follow slow drift in the real system.
- Particle filters need a prior that covers the truth and many more members than an EnKF.
- Use an explicit RNG (`rng = Xoshiro(seed)`) for reproducible runs and exact
  `snapshot`/`restore!` round trips.
